    Audit 023 — What must close before backends move onto the contract kernel¶

    Date: 2026-10-17

    Motivation: RFC-0017 moves every backend onto one contract kernel, a new interaction between Store, kernel and driver (D3 steps 2 to 8). That move is sound only once the specs and open design issues the kernel rests on are closed; otherwise each migration re-decides them, differently. The Memory drivers are the means of this audit, not its subject: they are the only drivers on the kernel today, so what they and the kernel leave unspecified, unpinned or contradictory is what every migrated backend would inherit.

    Scope: The RFC-0017 contract kernel (src/remote_store/_kernel/, async source and generated sync twin), MemoryDriver and AsyncMemoryDriver (backends/_memory.py, backends/_memory_tree.py, aio/backends/_memory.py) and the public remote_store.drivers, at 52448e0. Read against spec 003 (BE-0xx, BE-032 Appendix A), 013, 018, 029, 045, 051, the kernel's design (RFC-0017 D1, D2 and D5, ADR-0042), the driver docs (docs-src/reference/api/drivers.md, docs-src/guides/custom-backend-guide.md), the formal model (BackendContract.dfy, MemoryBackend.dfy, RootPath.dfy, StoreTree.dfy) and the tests under tests/_kernel/, tests/backends/memory/ and the conformance cells Memory runs. The question: where spec, code, tests and model disagree, or a clause is unspecified or unpinned, that must be closed before backends migrate.

    Excluded, already filed: BK-439, BK-438, BK-446, BK-447, BUG-334, BK-436, BK-435, BK-390, BK-345. A finding below touches one of them only where it says so.

    Method: six read-only passes, one per cluster: kernel contract, Memory drivers, async parity, glob and tree, formal model, driver docs. Each behavioural claim was measured with a probe script on 52448e0 (hatch run python), most against a subclass of MemoryDriver or the kernel test fake tests/_kernel/_fake.py with one primitive overridden; the output is quoted under each finding. A second reader then re-checked each finding and records how on its Checked: line (or in the § Lower-ranked Checked column): the probe re-run, the cited line opened, a grep or command run, or "first pass only" where it was not repeated.

    Probes: committed in audit-023-probes/, one directory per pass (c1 kernel to c6 docs) plus the second reader's lead_v_meta.py and lead_v_write_alias.py. hatch run python sdd/audits/audit-023-probes/run_all.py, from the repo root, runs all 32 and records each output beside it as <probe>.out; the committed .out files are the run this audit quotes, at 52448e0 on CPython 3.13.16. Timestamps, temp names and object addresses differ between runs.

    Tool state at the audit: dafny 4.11.0, dafny verify on the four files 1953 verified and 0 errors; hatch run check-dafny-oracle-fresh fresh; hatch run gen-sync-kernel-check "up to date"; hatch run lint exit 0.

    This is a report-only audit; nothing was modified. Dispositions are advisory.

    Severity key: 🔴 High · 🟠 Medium · 🟡 Low.

    Summary¶

    The kernel's pipeline is sound; what it trusts from a driver is not pinned. The BE-030 order, addressing, the choke point, BE-031, BE-017 and BE-029 match the spec and are pinned by named tests (§ Checked clean). The findings cluster where the kernel takes a driver's word without a clause or a check: a mapping it hands out uncopied (T1), a protocol body it never looks behind (T2), keys and declarations it does not validate (T9, T10), and stream errors it maps three ways (T4, T5). Around those calls, no protocol states who may call what in which state (T20). The formal model trails the kernel where P3 collects it: T3, T12, T13, T14, T19's model half, and the lower-ranked StoreTree names and negative max_depth rows; T3 would fail a correct test.

    The tree concepts are sound; the boundary lacks three. The tree came back clean (§ Checked clean). The boundary between Store, kernel, driver and Session lacks an interaction protocol with states (T20), a fault taxonomy that tells a wire error from a programming error by rule (T4, T5), and one meaning per capability flag across runtimes (T6). The remaining findings are bindings: existing concepts not yet wired to glob, the formal model, a flat template, or the Store-kernel split. Seven proposals (§ Proposals, P0 to P6) close both kinds; T1 to T16, T19 and T20 each name the one that absorbs them; T17, T18 and most lower-ranked rows are direct fixes with no open choice.

    Recommendations from triage. Each item is placed by one criterion: does closing it change what a migrating driver implements or may rely on?

    • (a) Before D3 step 2: P0 (T20), P1 (T1, T2, T4, T5, T9, T10, T11, T13's driver half, T15, T16), P2 (T7, T8; S3Boto3Backend declares GLOB, _s3_boto3.py:88, and globs through pattern_to_regex, :809), P4 (step 2's S3 is the first flat driver) and P5 (T6).
    • (b) Before the migration finishes (D3 step 8): P3 (T3, T12, T13's model half, T14, T19's model half), P6, T17, T18 and T19's test half. P3 moves to (a) if the formal model is to gate step 2's own acceptance, as triage recommends it gate driver acceptance.

    T7 stays open (§ Open questions); the rows under § Lower-ranked are recorded, not gated. Effort was ruled out as an argument for or against a proposal; each is judged by whether later drivers need it and what it prevents. Like everything in an audit these are advisory (CLAUDE.md § Audits). Suggested home if adopted: a new ADR for the two-tier gate and the model's role, with a backlog item carrying the gate, the way BACKLOG already carries "due before" gates (BK-439).

    Findings¶

    T1 🔴 FileInfo.metadata is the live stored dict¶

    Proposal: P1. Kind: contradiction. Clause: FileInfo "Immutable snapshot" (_models.py:82), BE-019. Mutating a returned info's metadata mutates the stored file's, and copy leaves source and destination sharing one dict. On the write side, WriteResult.metadata is the caller's own dict.

    Checked: probes lead_v_meta.py, lead_v_write_alias.py and c2/measure.py § D, § F re-run; cited lines opened.

    • Code: _memory_tree.py:58 (metadata=node.metadata), :212 (copy stores entry.metadata); the kernel's _file_info passes it uncopied (_kernel/_async/kernel.py:635, sync :620) while it copies extra.
    • Probe: write a.txt with {"k": "v"}, mutate get_file_info("a.txt"), copy to b.txt, mutate b.txt's info. 
      sync stored after mutating info: {'k': 'MUTATED'}
sync src after mutating dst info: {'k': 'VIA_DST'}
async stored after mutating info: {'k': 'MUTATED'}
    • Write side: MemoryTree.put returns PutResult(metadata=metadata), the caller's mapping (_memory_tree.py:145; only the stored copy at :133 is copied); the kernel's _write_result passes it on (_async/kernel.py:149, sync :134). Probe: write with m = {"k": "v"}, then mutate m: 
      sync WriteResult.metadata after caller mutates its dict: {'k': 'CALLER'} | is caller's: True
async WriteResult.metadata after caller mutates its dict: {'k': 'CALLER'} | is caller's: True
    • Predates the kernel: git grep metadata 107a5a1 -- src/remote_store/backends/_memory.py shows the same at lines 459 and 619.
    • No MEM clause or test covers isolation.

    Template impact: the kernel never copies Entry.metadata, so every driver that returns its own mapping inherits it, and every driver that echoes the caller's in PutResult. Disposition: copy (or wrap read-only) in _file_info, _write_result and MemoryTree.copy; a conformance cell in both runtimes for each direction.

    T2 🟠 An optional protocol's own body passes construction and no-ops¶

    Proposal: P1. Kind: spec-gap, untested. Clause: BE-030 (construction refusals). A driver that subclasses SupportsCopy and SupportsRemoveFolder without overriding them constructs, and copy and delete_folder return success having done nothing.

    Checked: probes c1/probe4.py and c1/probe4_async.py re-run; cited lines opened.

    • Code: _check_construction refuses an inherited body only for _PRIMITIVE_BODIES, built from vars(AsyncDriver) (_kernel/_async/kernel.py:116-130); optional protocols are detected by isinstance alone (:325-336, sync _sync/kernel.py:310-321).
    • Probe (class Forgetful(_SyncBase, SupportsCopy, SupportsRemoveFolder), declares COPY): 
      copy returned; 'dst' in store: False

    Proposals¶

    Advisory, per CLAUDE.md § Audits: the diagnosis above is the audit's authority, and whoever implements a proposal re-weighs it against the findings it cites. Each proposal is required because a later driver inherits the gap it closes; none adds a tree axiom, since the tree came back clean.

    P0 An interaction protocol with states¶

    Claim. Store, kernel, driver and Session interact through calls whose legality and cleanup depend on state, yet only the calls are specified (T20). P0 states the interaction as a protocol: the parties' states, the transitions each call, failure, cancellation and close takes, and the party that owns each exit. It is the frame P1's clauses and P5's flag meanings sit in.

    It decides:

    • the state sets: the backend (constructed, open, closed terminal or not, BE-020); the Session (unconnected, connected, condemned, reconnecting, RFC-0017 D5); and per operation a read stream (opened, iterating, exhausted, failed, abandoned, closed), a write handle (opened, committed, aborted), a listing's cursor, and a caller's content iterator (BK-448);
    • each call's meaning in each state: the closed guard, unwrap, a repeated close, when a refusal surfaces (at the call or at the first iteration);
    • the owner of each exit on every path, cancellation included: who closes a stream after a failure, who aborts a handle, who invalidates a condemned connection and who skips the second wait on it (SIO-010's async gap);
    • where it is stated and checked: a spec 003 section, a state model in the formal layer (the TLA+ Observer.tla or ResourceSafety.dfy's state tracking are the precedents), and one conformance cell per transition, run against a session-less and a Session driver.

    Absorbs: T20, the state half of T5, T11 and T16; the lower-ranked rows on repeated close, async connection_dead, cancellation routes and async refusal timing; BK-448.

    P1 Driver boundary contract¶

    Claim. Every later driver implements the boundary between what it observes and what the kernel decodes, and that boundary's failures are wrong answers, not errors. Today the trust is partly stated (BE-032 A.8's obligations), partly unchecked, and partly enforced only by Memory, and the kernel decodes driver records at scattered sites: _keys.listable filters at async kernel.py:1119, 1134, 1254, 1470-1473, 1525 (rg -n "listable"), each a site a new operation must remember. The folder_stats push-down at :1277 returns a count, which no kernel step can filter, so its omission (T13) is a driver obligation, not a decode-step site. P1 gives every item one owner and enforces the kernel's items with one mechanism, so a new kernel operation cannot forget a check.

    Owners, each a kernel check, a driver obligation or a Session obligation (RFC-0017 D5):

    The same omission in a native aggregate (T13) driver obligation; the kernel cannot filter a count stated with SupportsFolderStats
    Metadata in FileInfo and WriteResult is a copy (T1); {} against None (T15) kernel check decode step

    The mechanisms:

    • (b) One stream adapter shared by read, read_bytes and the ranged read: one caught set, one close policy, one cancellation path.
    • (c) One declaration record validated once at construction: namespace, parents, capabilities, presented protocols with the body check, rename_replaces, ensure_parents.

    The absorbed findings become the acceptance tests of (a), (b) and (c).

    Absorbs: T1, T2, T4, T5, T9, T10, T11, T13 (driver half), T15, T16; the lower-ranked rows on return shapes, container_absent, close repeatability, the self-move precondition and async connection_dead.

    P2 Glob in tree terms¶

    Claim. glob is the one folder read that names no key, so BE-032 can only approximate it ("over its pattern's literal prefix"), and fallback and native already disagree on one tree (T8). P2 defines glob(p) as the files of the tree whose path matches p, makes the kernel's prefix listing and probes optimisations judged against that, and fixes one pattern dialect.

    It decides: the defining clause and how A.5 cites it (which decides T7's open question); whether a character class may match /; what ^ means in a class; ** as a whole segment only; the error type of a malformed pattern; what \ means (BK-447).

    Absorbs: T7, T8, BK-439, BK-447; the lower-ranked rows on GLOB-012's prose, GLOB-015, and Tier-1 case folding.

    P3 One formal truth¶

    Claim. StoreTree.dfy states the tree; BackendContract.dfy, which the compiled oracle runs, still ranges over a path map and never sees an encoding (BK-434). Two models of one store drift: T3, T12, T13, T14, T19's model half, the StoreTree name gap and the negative max_depth row are that drift. In T3, T12 and T14 the model, not the kernel, was wrong; in T13 both were. Recommended at triage: the model gates driver acceptance, so BackendContract is refined against StoreTree, with BE-030's key rule inside its domain.

    It decides: BK-434's open choice (refinement lemmas per encoding, or one encoding-parametric trait); how the oracle adapter reaches the key rule instead of passing raw keys (T14); the trait methods the model lacks (read_bytes, read_seekable, write_atomic, open_atomic, iter_children, glob, check_health, and the non-I/O members, T12), including glob, whose exclusion premise (BackendContract.dfy:89-92) is stale and which P2 redefines; where kernel-only cells count for traceability.

    Absorbs: T3, T12, T13 (model half), T14, T19 (whether the contract owns copy and move mtime); the lower-ranked rows on StoreTree names, negative max_depth, and BE-030/031 traceability.

    P4 The template is a set: Memory and a flat reference driver¶

    Claim. Both Memory drivers are hierarchical with implicit parents (backends/_memory.py:43-44, aio/backends/_memory.py:39-40) and hold the tree directly, so flat decoding, the list_page byte-order obligation, A.3's shadow omission and stat, and A.4's ancestor checks run only against the kernel's test fake (tests/_kernel/_cells.py:37-42, shape flat-none). The flat drivers of D3 (S3, Azure, SQLAlchemy) would have no reference to copy, and the first of them would become the template by accident. P4 makes the template a reference set with a flat member.

    It decides: the members of the set; which kernel and conformance cells each runs; that both Memory drivers present SupportsGlob, so P2 has a real runner (BK-446).

    Absorbs: the template coverage behind T13 and BK-446; the lower-ranked row on MEM-tagged cells that never run on async Memory, for the async member.

    P5 One meaning per capability flag, checked in each runtime¶

    Claim. One CapabilitySet crosses runtimes unchanged: the sync kernel is generated from the async source, and ASYNC-084 preserves a flag through the sync adapter. A flag that promised different things per runtime would carry a different promise through every adapter, so a caller checking LAZY_READ on an adapted backend could not know which holds. P5 gives each flag one meaning and checks it by conformance in both runtimes; where an async read cannot keep a flag's meaning, the async side withholds the flag rather than redefine it.

    It decides: LAZY_READ as per-chunk pull, so a read holds at most a chunk, never the file (T6's reasoning; CAP-007 and SIO-009 already say so for sync); SEEKABLE_READ withheld by async backends, whose read is a forward-only generator; whether any other flag cannot hold across runtimes; the async conformance cell that replaces the e2e exemption.

    Absorbs: T6.

    P6 One owner per check between Store and kernel¶

    Claim. Two layers own the same checks. Store gates capabilities per operation (_store.py:1011-1017, 18 call sites by rg "self._gate\(" src/remote_store/_store.py, move at :631, copy at :665) and validates paths through RemotePath (_full_path, :1019-1032); the kernel also gates capabilities (BE-030; T12) and validates and normalises keys (BE-030). Each migrated backend inherits whichever split is in place. P6 assigns each check to one layer.

    It decides: which layer owns capability gating, path validation and normalisation, and error-path attribution (canonical or raw, the lower-ranked row); what the other layer keeps (none, or a documented fast path); BE-027's text once the answer is in place.

    Absorbs: T12 (prose half, BE-027); the lower-ranked row on error path spelling.
