## Pitfalls comparables met

Move or rename: Copy plus delete is neither atomic nor cheap. Atomic only on some bucket types: Azure HNS, GCS `move_blob` within a bucket, S3 `RenameObject` on Express One Zone. SFTP v3 rename fails if the target exists. Same-path moves differ; GCS charges early deletion on a copy-based move.

## Findings in the research's results

Q3, gating: OpenDAL gates create_dir, rename, copy, recursive listing, user
metadata, append, presign and the conditional and versioned variants, which
matches the catalogue's optional OP-19 and OP-20.

Q3, gating: Several gates depend on bucket or account type and are only found at
runtime: Azure rename and recursive delete need a hierarchical namespace, S3
`RenameObject` needs Express One Zone.

Q3, gating: Silent emulation or no-op: fsspec `mkdir` does nothing and `mv` is
copy plus delete; cloudpathlib `mkdir` does nothing; pyarrow drops metadata
keys; smart_open ignores unknown parameters.
