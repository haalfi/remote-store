## Findings in the research's results

Q2, the cut, write, atomic replace, conditional write (OP-03 to OP-05): The
comparables merge them: a condition is a mode of put (object_store
`PutMode::{Overwrite, Create, Update}`, every put atomic), and the vendor stores
attach conditions to read, delete, copy, rename and metadata update as well.
OpenDAL publishes a conditional-operations specification: a condition is never
silently ignored, a mutation condition is advertised only if it is evaluated
atomically with the visible commit (stat-then-mutate emulation is forbidden),
staged writes evaluate it at the final commit, and where the error surfaces is
unspecified. fsspec's `mode="create"` is exactly that forbidden emulation
(inference). Atomic replace is a separate operation only on filesystems
(`os.replace`, SFTP `posix_rename`); on object stores every PUT is atomic.

Q2, the cut, read (OP-01, OP-02): pyarrow splits sequential from random reads;
object_store folds ranges into one get with options.

## Decisions comparables made once for every operation

Q4, decided once for every operation: Error taxonomy: object_store `Error` enum
and OpenDAL `ErrorKind`, each with NotFound, AlreadyExists, a precondition kind
and an unsupported kind; gocloud `ErrorCode`; fsspec and pyarrow builtins.

Q4, decided once for every operation: Retries: object_store built in, retrying a
timeout only if the request is idempotent; OpenDAL opt-in, temporary errors
only; s3fs an allow-list; gocloud not portable (inference); GCS retries deletes
by default.

Q4, decided once for every operation: Timeouts: per instance or per call:
object_store 30 s, OpenDAL 60 s (opt-in), botocore 60 s, Azure 20 s to connect
and 60 s to read, GCS 60 s; gocloud per call.

Q4, decided once for every operation: Consistency stated: atomic put
(object_store); strong read-after-write including list (S3, Azure, GCS);
gocloud's list may miss recent writes.

Q4, decided once for every operation: Identity token: ETag and version are
opaque. An S3 ETag is an MD5 only for a single-part plaintext or SSE-S3 upload;
multipart, SSE-C/KMS and directory buckets give no MD5, and a metadata-only
change leaves the ETag alone.

Q4, decided once for every operation: Closing: gocloud `Bucket.Close`; vendor
`close()`; OpenDAL `Operator`, fsspec and pyarrow have none; object_store relies
on Drop (inference).

Q4, decided once for every operation: Prefix scope (OP-16): object_store
`PrefixStore`, OpenDAL `root`, gocloud `PrefixedBucket`, fsspec `DirFileSystem`,
pyarrow `SubTreeFileSystem`.

Advisory note 7 (the report's, not a decision): **Shared decisions most often
retrofitted:** `..` containment, missing-key delete, exception typing in Python
bindings, sync and async parity in bindings, retry coupled to idempotency,
behaviour on an exception during a streamed write.
