## Environment

Decided in the first dialog as drafted, E1 to E14. Steps of an OP-01 call, referenced as
*s1* to *s4*: s1 key reduction (ν, spec 052), s2 classification of the key
against the store, s3 content transfer (the whole read's, or each read on a
stream), s4 the stream's close.

| ID | Actor | Action |
|---|---|---|
| `OP-01/E1` | O2 | Creates or replaces an item through the API, whole or streamed |

| `OP-01/E3` | O3 | Replaces an item's content as one step in the backing storage (a new object version, a rename over the file) |

## Decisions

### OP-01/D1: Forms (AX-1)

- **Scenario:** a caller reads a 2 KB config as text, and a 40 GB item chunk
  by chunk.
- **Options:** (a) whole bytes, whole text, a sequential binary stream;
  (b) (a) plus a text stream, the library owning streaming decode; (c) bytes
  and stream only, every caller decoding.
- **Recommendation:** (a). Whole bytes and text serve N-01, the stream N-02; a
  text stream is the caller wrapping the binary one. Source: catalogue N-01,
  N-02; prior art object_store `get` (bytes or stream), OpenDAL read and
  reader, pyarrow `open_input_stream`, none with a text stream.
- **Decision:** (a). OP-01 offers three operations: whole bytes, whole text,
  and a binary stream, each in a sync and an async form. None takes an offset
  or range: reading at offsets is OP-02's.
- **Consistency check:** a question no axis raises (forms), asked under AX-1
  per the Rules; name it when the axes are revised with F2. Agrees with
  OPS-001, OPS-002 and the catalogue's OP-01/OP-02 cut. That both forms
  behave alike is this entry's to state (shared.md Lands elsewhere, Sync and
  async parity): every later decision binds both unless it says otherwise.
- **Open items:** none.

### OP-01/D2: The stream's shape (AX-1)

- **Scenario:** a caller passes the stream to `shutil.copyfileobj`, wraps it
  for line-by-line text, or hands it to pyarrow's Parquet reader, which seeks.
- **Options:** (a) a sequential binary file object: `read(n)`, `readinto`,
  `readline` and line iteration, `close`, context manager, not seekable;
  (b) a chunk iterator only; (c) the file object of (a) plus an explicit
  chunk iterator. Follow-up, whether the file object seeks: (i) not
  seekable, Parquet reads through OP-02's reader; (ii) seekable, folding
  OP-02 into OP-01, a catalogue reopen; (iii) forward-only seek, which
  Parquet's footer-first read does not satisfy.
- **Recommendation:** (a), then (i). Source: Python `io.BufferedIOBase`;
  fsspec `open`, pyarrow `NativeFile`; catalogue OP-01/OP-02 and the session
  input's "pyarrow splits sequential from random reads".
- **Decision:** (c) and (i): a sequential, non-seekable binary file object
  that also offers an explicit chunk iterator. The maintainer's reason: it
  fits every need known so far. Random access, Parquet's included, is
  OP-02's.
- **Consistency check:** keeps the catalogue cut (no reopen). Both
  consumption styles, `read` and the chunk iterator, draw from one position,
  so AX-6 states every state's cell for each.
- **Open items:** `OP-01/O1`.

### OP-01/D3: The text form's parameters (AX-1)

- **Scenario:** an item holds Latin-1 bytes; the caller's locale is cp1252.
- **Options:** (a) `encoding` default UTF-8 and `errors` default strict,
  both fixed by the library, never the locale; (b) UTF-8 strict with no
  parameters; (c) `encoding` defaulting to the locale.
- **Recommendation:** (a): one input reads alike on every host. Source:
  PEP 686 (UTF-8 default), `bytes.decode`'s parameters; PEP 597 against (c).
- **Decision:** (a).
- **Consistency check:** consistent with D1. What the decoded value is, from
  bytes and the two parameters, is AX-2's; what a decode failure surfaces as
  is AX-10's.
- **Open items:** none.

### OP-01/D4: The root (AX-1)

- **Scenario:** `read('')` or `read('a/..')`, which ν reduces to ε, and
  Ω_S(ε) = Found(r, folder).
- **Options:** (a) no special clause: the root fails as any folder key does;
  (b) refused before any backend contact, like a refused key.
- **Recommendation:** (a). Source: KEY-013 and spec 052 Notes (The root),
  TREE-002.
- **Decision:** (a). The addressed structure: OP-01 is meaningful exactly for
  an accepted input k = ν_c(p) with Ω_S(k) = Found(e, item); every other
  pre-state is a failure whose category AX-3 and AX-10 fix.
- **Consistency check:** consistent with KEY-001 (refusal by ν is a function
  of input and configuration, so it needs no store state) and KEY-013.
- **Open items:** none.

### OP-01/D5: The text value (AX-2)

- **Scenario:** an item holds `b'\xef\xbb\xbfa\r\nb'`, read as text with the
  defaults.
- **Options:** (a) exactly `bytes.decode(encoding, errors)`: `'\ufeffa\r\nb'`;
  (b) universal newlines as `open()`: `'\ufeffa\nb'`; (c) strip a UTF-8 BOM
  by default: `'a\r\nb'`.
- **Recommendation:** (a): a pure function of the bytes form's value and
  D3's parameters, the same on every backend and host, and round-tripping
  with the bytes form. Source: `bytes.decode`; AX-2's normative form.
- **Decision:** (a). text(k, enc, err) = decode(bytes(k), enc, err), where
  bytes(k) is what the bytes form would return for the same version (AX-8);
  no newline translation, a BOM kept unless the caller names `utf-8-sig`.
- **Consistency check:** consistent with D1 and D3. Total over every byte
  string with `errors` other than strict; under strict, a decode failure is
  AX-10's.
- **Open items:** none.

### OP-01/D6: `read(n)` on the stream (AX-2)

- **Scenario:** 10 bytes remain and the backend's next network chunk holds 3;
  the caller calls `read(8)`.
- **Options:** (a) exactly n bytes unless fewer remain, `b''` only at the
  end, `read()` or `read(-1)` the rest; (b) 1 to n bytes, raw semantics.
- **Recommendation:** (a): what callers of a buffered file expect. Source:
  `io.BufferedIOBase.read`; fsspec `AbstractBufferedFile`.
- **Decision:** (a). With r bytes remaining, `read(n)` for n ≥ 0 returns
  min(n, r) bytes, the next ones of the content; `read(n)` for n < 0 returns
  all r. Bytes returned across all reads and chunks, in order, are a prefix of
  the content, the whole content once `b''` is returned.
- **Consistency check:** consistent with D2 (one position for `read` and
  chunks). "The content" is the one version AX-8 fixes.
- **Open items:** none.

### OP-01/D7: The chunk iterator (AX-2)

- **Scenario:** the caller iterates chunks of size 1 MiB over a 2.5 MiB item.
- **Options:** (a) every chunk non-empty and at most size bytes, their
  concatenation the remaining content; (b) exactly size, the last shorter;
  (c) no size parameter.
- **Recommendation:** (a): boundaries follow the transfer, with no re-buffer.
  Source: object_store's byte stream; aiohttp `iter_chunked`.
- **Decision:** (a). The iterator takes a positive size; it yields non-empty
  chunks of at most size bytes, starting at the stream's current position,
  whose concatenation is the content from there to the end, and stops at the
  end. Exact chunk sizes are not promised (AX-14).
- **Consistency check:** consistent with D2 and D6: chunks and `read` advance
  one position. A non-positive size is a caller error, AX-10's.
- **Open items:** none.

### OP-01/D8: Missing keys (AX-3)

- **Scenario:** `a.txt` is an item; the caller reads `x` (Absent), `p/q/x`
  with no `p` (AbsentAncestor) and `a.txt/b` (BlockedByItem).
- **Options:** (a) one NotFound category for all three; (b) NotFound
  carrying kⱼ, which costs a listing or stat walk on object stores;
  (c) three distinct categories, at the same cost.
- **Recommendation:** (a): a reader can act on none of the differences, and
  on S3 all three are one 404. Source: spec 052 Notes (Resolution's
  outcomes: BlockedByItem is apart for writes); object_store `NotFound`.
- **Decision:** (a).
- **Consistency check:** consistent with KEY-013; no ground clause makes the
  three outcomes observable through every operation. Category names here are
  working names; their home is the error layer (AX-10).
- **Open items:** none.

### OP-01/D9: A folder key, and the partition (AX-3)

- **Scenario:** `d/f` is an item, so `d` is a folder; on S3 a GET on `d`
  answers 404. The caller reads `d`, or the root (D4).
- **Options:** (a) its own category, not an item; object-store backends tell
  a folder from absence with one listing request on the failure path only;
  (b) NotFound, as object_store does; (c) profile-declared, not-an-item only
  where the backend tells folders natively.
- **Recommendation:** (a): it agrees with OP-09, which reports `d` as an
  existing folder. Source: TREE-001, KEY-013 Found(e, folder); session input
  pitfall "object_store returns NotFound on a folder path".
- **Decision:** (a). The complete partition, every form, by pre-state at
  classification (s2; AX-8 fixes when that instant is):

  | Pre-state | Outcome |
  |---|---|
  | ν_c(p) refused (KEY-002, KEY-004, KEY-005) | failure: key refused, the category shared with every operation |
  | Ω_S(k) = Found(e, item) | success: e's content (empty for an empty item), as bytes, as text (D5), or as a stream positioned at 0 |
  | Ω_S(k) = Found(e, folder), the root included | failure: not an item |
  | Ω_S(k) = Absent, AbsentAncestor(kⱼ) or BlockedByItem(kⱼ) | failure: not found |

  The rows are disjoint and complete: ν refuses or accepts (KEY-001), and
  KEY-013 gives exactly one Ω case, Found split by TREE-001's partition.
  Failures that depend on the environment rather than the pre-state (access,
  transport, decode) are AX-10's.
- **Consistency check:** consistent with D4 and D8. The key-refused row
  follows shared.md Lands elsewhere ("An unacceptable key refused identically
  by every operation"). The extra listing request is a request count, AX-14's.
- **Open items:** none.

### OP-01/D10: The store's frame (AX-4)

- **Scenario:** O1 reads `a.txt` (success) and `d` (not an item); on Local
  the read bumps the file's atime, on S3 it adds a GET to the access log.
- **Options:** (a) nothing any API call observes changes; effects seen only
  out of band are registered non-promises; (b) also promise no out-of-band
  effect, which needs `noatime` on Local and is impossible for S3 logs.
- **Recommendation:** (a). Source: spec 051's store tuple; RFC 9110 § 9.2.1
  (GET is safe).
- **Decision:** (a). After any OP-01 call, successful or failed, and after
  any use or close of its stream, the store's state (U, F, I, r, C, name) and
  every property OP-09 and OP-20 report are those the environment alone
  leaves. Atime, access logs and billing are AX-14's.
- **Consistency check:** consistent with D9 (failures change nothing either)
  and spec 051. Binds OP-09 and OP-20: modification time must be one that a
  read leaves alone, so neither may report atime as it.
- **Open items:** `OP-01/O2`.

### OP-01/D11: The handle's state (AX-4)

- **Scenario:** O1 reads `a.txt`, O3 replaces it (E3), O1 reads again through
  the same handle.
- **Options:** (a) the handle holds only configuration and lifetime: no
  content or metadata cache; (b) an opt-in cache per store; (c) an s3fs-style
  metadata cache with expiry.
- **Recommendation:** (a). Source: object_store `ObjectStore`, gocloud
  `Bucket`; session input pitfall "s3fs added ETag expiry checks".
- **Decision:** (a). A handle holds, between calls, its configuration and
  its lifetime and nothing else that changes an operation's outcome;
  connection pools and credential refresh may be held but change none. Every
  call classifies and transfers afresh. The maintainer's reason: caching, if
  wanted, is a later extension that owns its own state; the store handle
  stays clean.
- **Consistency check:** binds every operation, so listed as a shared
  decision (`OP-01/O3`). Consistent with spec 053 Notes (Extensions: an
  extension adds a feature on top of the entries).
- **Open items:** `OP-01/O3`.

### OP-01/D12: The timeout model (AX-5)

- **Scenario:** E9, the backend accepts the connection and sends nothing;
  separately, a healthy 40 GB read takes 20 minutes.
- **Options:** (a) a connect timeout and an idle (no-progress) timeout, no
  whole-call deadline; (b) (a) plus a whole-call deadline T_total; (c) each
  backend client's own defaults, profile-declared.
- **Recommendation:** (a): a progressing transfer never fails by its size.
  Source: botocore connect and read timeouts; Azure 20 s connect, 60 s read
  (session input, Q4 Timeouts).
- **Decision:** (a). Under a quiet environment every OP-01 call, and every
  read on its stream, returns or fails. A network backend's request fails with
  the timeout category when connecting takes longer than T_connect, or when no
  byte arrives for T_idle while the library waits on the backend; time the
  caller spends between stream reads never counts. No whole-call deadline: the
  maintainer leaves one to a later convenience extension or a
  profile-declared backend option.
- **Consistency check:** binds every operation (shared.md Lands elsewhere, A
  timeout bound: "a bound shared by every operation, OP-01's flow"), so
  listed as `OP-01/O4`. The bound is per backend request; how many requests a
  retrying call makes is AX-13's, which therefore bounds the call's total.
  Total duration is AX-14's.
- **Open items:** `OP-01/O4`.

### OP-01/D13: The timeout defaults (AX-5)

- **Scenario:** a store configured with no timeouts.
- **Options:** (a) T_connect 20 s, T_idle 60 s for every network backend;
  (b) 10 s and 30 s; (c) each backend's own default, a profile row.
- **Recommendation:** (a). Source: session input, Q4 Timeouts (object_store
  30 s, OpenDAL 60 s, botocore 60 s, Azure 20 s and 60 s, GCS 60 s).
- **Decision:** (a). Both are store configuration; these are the defaults.
- **Consistency check:** consistent with D11 (configuration is handle state
  that may change an outcome). Shared with D12, `OP-01/O4`.
- **Open items:** `OP-01/O4`.

### OP-01/D14: Local I/O termination (AX-5)

- **Scenario:** a Local store on an NFS mount whose server vanished; a read
  syscall blocks in the kernel.
- **Options:** (a) a profile deviation: termination rests on the OS's I/O
  completing, no library timeout; (b) a library timeout through a helper
  thread, which leaves a blocked thread behind.
- **Recommendation:** (a). Source: AX-15's form; pyarrow `LocalFileSystem`
  and fsspec's local file system time out no read.
- **Decision:** (a). Normal value: D12's bound. Declared deviation: Local,
  and the server-side file system behind SFTP once the SFTP request is sent,
  terminate when the OS's I/O completes.
- **Consistency check:** a variation point, so recorded again under AX-15.
  An SFTP request still meets D12's T_idle on the network side; only a server
  that keeps the channel alive while its disk hangs falls under the
  deviation.
- **Open items:** none.

### OP-01/D15: The Closed state (AX-6)

- **Scenario:** the caller leaves a `with` block, then calls `read(10)` and
  `close()` again.
- **Options:** (a) Python io semantics: reads raise `ValueError`, a second
  close is a no-op; (b) a library "closed" category.
- **Recommendation:** (a): nothing about the store happened, and wrappers
  expect file-object behaviour. Source: `io.IOBase.close`.
- **Decision:** (a), in both forms.
- **Consistency check:** consistent with D2 (a file object). `ValueError` is
  a caller error, not a storage category (AX-10).
- **Open items:** none.

### OP-01/D16: The Failed state (AX-6)

- **Scenario:** a stream read surfaces a transport failure the library's own
  recovery (AX-13) could not mend; the caller catches it and reads again.
- **Options:** (a) sticky: every later read raises the same category, close
  works; (b) later reads try to resume; (c) the stream becomes Closed.
- **Recommendation:** (a): the caller never gets bytes after a gap, and
  recovery has one place, inside a read. Source: Go `bufio.Reader`'s sticky
  error.
- **Decision:** (a). A caller who wants to go on makes a new OP-01 call.
- **Consistency check:** consistent with D6 (returned bytes are a prefix of
  the content). Recovery inside a read is AX-13's.
- **Open items:** none.

### OP-01/D17: An unclosed stream (AX-6)

- **Scenario:** the caller drops the last reference to an open stream.
- **Options:** (a) released when collected, with a `ResourceWarning`;
  (b) released silently.
- **Recommendation:** (a). Source: CPython file objects.
- **Decision:** (a). When collection happens is AX-14's.
- **Consistency check:** consistent with D10: release changes no store state.
- **Open items:** none.

### OP-01/D18: The handle's lifetime ends while a stream is open (AX-6)

- **Scenario:** a stream is open, its handle is closed, then
  `stream.read(10)`.
- **Options:** (a) leave the cell open for OP-21's session; (b) decide now
  that the stream outlives the handle; (c) decide now that it fails.
- **Recommendation:** (a): OP-21 decides how a lifetime ends for every
  handed-out resource at once. Source: shared.md § Lifetime.
- **Decision:** (a). The stream's transitions, the open cells excepted:

  | State | `read`, `readinto`, `readline`, chunks | `close` | handle's lifetime ends |
  |---|---|---|---|
  | Open (bytes remain) | next bytes (D6, D7); a failure moves to Failed | releases; Closed | open: `OP-01/O5` |
  | Exhausted (at end) | `b''`, an empty iteration | releases; Closed | open: `OP-01/O5` |
  | Failed | the same failure again (D16) | releases; Closed | open: `OP-01/O5` |
  | Closed | `ValueError` (D15) | no-op | no effect |

  A stream starts Open, or Exhausted for an empty item; dropping it unclosed
  releases it when collected (D17). Cancellation is AX-7's.
- **Consistency check:** consistent with D15 to D17. Lifetime binds every
  operation that hands out a resource, so `OP-01/O5` is shared.
- **Open items:** `OP-01/O5`.

### OP-01/D19: An item that exists but cannot be read now (AX-7)

- **Scenario:** O3 moves `cold.bin` to S3 Glacier Flexible Retrieval or Azure
  Archive; OP-09 still sees the item, but a GET answers "restore first".
- **Options:** (a) add E15, O3 makes an item unreadable in place;
  (b) fold it into E6 as permission denied; (c) out of scope, the native
  error surfacing through the catch-all category.
- **Recommendation:** (a). Source: S3 `InvalidObjectState`, Azure
  `BlobArchived`.
- **Decision:** (a): E15 joins the Environment. Exposure of OP-01's steps
  (s1 reduction, s2 classification, s3 transfer, s4 close):

  | Row | s1 | s2 | s3 | s4 | Home |
  |---|---|---|---|---|---|
  | E1, E2 (O2) | — | yes | yes | — | AX-8 |
  | E3, E4, E5 (O3) | — | yes | yes | — | AX-9 |
  | E6, E15 (O3) | — | yes | yes | — | AX-10 |
  | E7 to E13 (world) | — | yes | yes | — | AX-10 to AX-13 |
  | E14 (runtime) | yes | yes | yes | — | D20 |

  s1 is a function of input and configuration (KEY-001), so only E14 reaches
  it; s4 releases a resource and reports nothing (AX-11).
- **Consistency check:** E15 is the first Environment addition by decision
  (axes.md § Vocabulary). Its category is AX-10's. No other entry's list is
  admitted to the ground yet, so there is none to compare with.
- **Open items:** none.

### OP-01/D20: Cancellation (AX-7)

- **Scenario:** an asyncio task awaiting `stream.read(1 MiB)` is cancelled
  with bytes half-received; or `KeyboardInterrupt` in the sync form.
- **Options:** (a) the stream becomes Closed, its resources released;
  (b) Failed, sticky, which needs an "interrupted" category; (c) Open with
  the position unchanged, which no backend transport can promise.
- **Recommendation:** (a): nothing claims a position no one can know.
  Source: unsourced (asyncio promises no position after a cancelled read).
- **Decision:** (a). Cancellation propagates to the caller unchanged; a
  cancelled stream read releases the stream, which is then Closed (D15). A
  cancelled whole read or stream open hands out nothing and changes nothing
  (D10).
- **Consistency check:** adds a transition to D18's table: Open, any read,
  cancelled → Closed. Consistent with D16 (cancellation is no storage
  failure, so not Failed).
- **Open items:** none.

### OP-01/D21: A whole read overlapping a write (AX-8)

- **Scenario:** `a` holds v1; O2 replaces it with v2 (E1) while O1's whole
  read of `a` is in flight.
- **Options:** (a) one version, the content at one instant inside the read's
  interval; (b) one version only against OP-04 writes, a mix possible during
  an OP-03 write on file-system backends.
- **Recommendation:** (a). Source: session input, Q4 Consistency stated
  ("atomic put (object_store)"); Herlihy and Wing, linearizability.
- **Decision:** (a). For every history of O1's whole read (bytes or text)
  with overlapping O2 calls, there is an instant t inside the read's interval
  such that the outcome is D9's row for the pre-state at t, with the content
  the item had at t. Classification and content come from that one instant.
- **Consistency check:** requires every API mutation to change an item's
  content atomically as a reader sees it, so no reader meets a state between
  two contents: a constraint on OP-03 to OP-05 and OP-12 to OP-15
  (`OP-01/O6`). O3's rights are AX-9's.
- **Open items:** `OP-01/O6`.

### OP-01/D22: A stream overlapping a write (AX-8)

- **Scenario:** O1 opens a stream on `a` (v1) and reads 1 GB; O2 replaces `a`
  with v2 or deletes it; the stream needs a new backend request for the rest.
- **Options:** (a) pinned to the version current at open, or the next read
  fails with a "changed" category; (b) pinned and bound to complete, which a
  non-versioned bucket cannot give after a reconnect; (c) an unspecified mix.
- **Recommendation:** (a). Source: session input pitfall "the view during a
  streamed read is undefined unless pinned; s3fs added ETag expiry checks".
- **Decision:** (a). The stream is one interval operation with one output:
  the open classifies at one instant t₀ inside the open call (D9's rows), and
  every byte the stream delivers is a byte of the content at t₀, at its
  position. If the backend can no longer serve that content, the read that
  needs it fails with the changed category and the stream is Failed (D16);
  bytes from another content, or after a gap, are never delivered.
- **Consistency check:** consistent with D6, D16, D21. A stream on an empty
  item is Exhausted at open and meets nothing later (D18). Whether a backend
  can keep serving the pinned content after a reconnect is a variation
  point (AX-15); the changed category is AX-10's.
- **Open items:** none.

### OP-01/D23: A read after a completed write (AX-8)

- **Scenario:** O2's write of v2 to `a` returns; then O1 starts a read of
  `a`.
- **Options:** (a) normal value: that write's content or a later one, an
  eventually consistent backend declaring the deviation; (b) always strong,
  no deviation; (c) eventual for every backend.
- **Recommendation:** (a). Source: session input, Q4 Consistency stated
  ("strong read-after-write including list (S3, Azure, GCS)").
- **Decision:** (a). Normal value: the instant t of D21 and t₀ of D22 lies
  after every API mutation that completed before the read started (real-time
  order); in particular O1 reads its own completed writes. Declared
  deviation: eventual, the read may see an earlier content for a bounded or
  unbounded time, as the backend's profile states.
- **Consistency check:** binds every write and every read entry, so shared:
  `OP-01/O7`. A profile variation (AX-15).
- **Open items:** `OP-01/O7`.

### OP-01/D24: One handle, concurrent callers (AX-8)

- **Scenario:** eight threads share one Store, or eight tasks one AsyncStore
  on its event loop, each reading.
- **Options:** (a) safe for concurrent calls, each behaving as if issued
  alone under D21 to D23; (b) one caller at a time per handle.
- **Recommendation:** (a). Source: object_store (`Send + Sync`), gocloud
  `Bucket`, boto3 clients.
- **Decision:** (a). Calls through one handle may overlap, from any threads
  (Store) or from tasks on one event loop (AsyncStore); O2 may be the same
  handle as O1. One stream serves one consumer at a time; concurrent use of
  one stream is not promised (AX-14).
- **Consistency check:** consistent with D11 (no per-call state in the
  handle). Binds every operation: `OP-01/O8`.
- **Open items:** `OP-01/O8`.

### OP-01/D25: O3 replaces or deletes in one step (AX-9)

- **Scenario:** during O1's stream on Local, O3 runs `mv new a` (E3) or
  `rm a` (E5); on S3, O3 PUTs or DELETEs `a` with the AWS CLI.
- **Options:** (a) the same rights as O2; (b) weaker, unspecified for O3.
- **Recommendation:** (a): it holds natively, since an open file descriptor
  keeps the old file and an S3 range read can be pinned by ETag. Source:
  POSIX `rename` and `unlink`; S3 `If-Match`.
- **Decision:** (a). D21 to D23 apply with O3's E3, E5 and E15 in place of
  O2's E1 and E2: one content per whole read, a stream pinned to its open's
  content or failing with the changed category. D23's real-time order is
  promised only for API mutations; when an O3 change becomes visible is the
  backend's.
- **Consistency check:** consistent with D21 to D23; adds no backend
  requirement beyond D22's variation point.
- **Open items:** none.

### OP-01/D26: O3 modifies in place (AX-9)

- **Scenario:** during O1's whole read or stream of a 10 GB file on Local or
  SFTP, O3 truncates it to 4 GB, or overwrites bytes 1 GB to 2 GB (E4).
- **Options:** (a) weaker rights, stated: each delivered byte is the file's
  byte at its position when it was read, no failure promised; (b) (a) plus
  best-effort size and mtime detection, still no promise; (c) the same
  rights as O2, which needs a snapshot or lock neither backend offers.
- **Recommendation:** (a). Source: POSIX `read(2)` gives no isolation from
  concurrent writers.
- **Decision:** (a). Under E4 during an OP-01 call or stream, D21's single
  instant and D22's pinning are deliberately not promised. What remains: every
  delivered byte is the byte the file held at that position at some instant
  between the open and that byte's delivery; the read ends at the end it
  meets; the call may complete without failing. A non-promise, scoped to E4
  on file-system backends (AX-14).
- **Consistency check:** narrows D21 and D22 for O3 only, so O3 has fewer
  rights than O2 (axes.md AX-9's open question, answered for OP-01). E4
  cannot arise on object stores, which have no in-place modification.
- **Open items:** none.

### OP-01/D27: The typing principle (AX-10)

- **Scenario:** a read fails with botocore `ClientError` 404, paramiko
  `SFTPError` or `OSError` ENOENT, depending on the backend.
- **Options:** (a) library categories under one base, each also a builtin
  where one fits, the native exception chained as `__cause__`; (b) library
  categories only; (c) builtins only, fsspec style.
- **Recommendation:** (a): `except FileNotFoundError` keeps working, and
  categories no builtin has (changed, unavailable) still get a type. Source:
  session input, Q4 Error taxonomy (object_store `Error`, OpenDAL
  `ErrorKind`; fsspec and pyarrow builtins).
- **Decision:** (a). Every storage failure surfaces as a library category,
  never as a backend's own exception; the native exception, where there is
  one, is its `__cause__`. Builtin parents so far: not found
  `FileNotFoundError`, not an item `IsADirectoryError`, permission denied and
  authentication failed `PermissionError`, timeout `TimeoutError`.
- **Consistency check:** the error layer's first clause: shared
  (`OP-01/O9`). Category names in this record are working names until that
  layer names them.
- **Open items:** `OP-01/O9`.

### OP-01/D28: Transport failures (AX-10)

- **Scenario:** E7 unreachable, E8 reset, E10 throttled, E12 short body, each
  after the library's own recovery (AX-13) is spent; and E9 a stall past
  T_idle.
- **Options:** (a) one unavailable category, timeout its subcategory;
  (b) separate unavailable and timeout; (c) one category per row.
- **Recommendation:** (a): one "try later" category. Source: OpenDAL
  `ErrorKind` (temporary vs permanent); gocloud `ErrorCode`.
- **Decision:** (a). E7, E8, E10 and E12 surface as unavailable, E9 as
  timeout (D12), which is an unavailable. A short or corrupt body is never
  returned as content.
- **Consistency check:** consistent with D12 and D16 (on a stream these move
  it to Failed). Shared: `OP-01/O9`.
- **Open items:** `OP-01/O9`.

### OP-01/D29: Access failures (AX-10)

- **Scenario:** E6, the caller lacks read rights on `a`; E11, the credentials
  are rejected or expire mid-stream.
- **Options:** (a) two categories, permission denied and authentication
  failed; (b) one, permission denied.
- **Recommendation:** (a): the fixes differ (grant rights, renew
  credentials), and every backend keeps them apart. Source: gocloud
  `ErrorCode` `PermissionDenied` vs `Unauthenticated` (the gRPC codes).
- **Decision:** (a), both under `PermissionError` (D27).
- **Consistency check:** consistent with D27. Shared: `OP-01/O9`.
- **Open items:** `OP-01/O9`.

### OP-01/D30: An item that cannot be read now (AX-10)

- **Scenario:** E15, an archive tier or a missing customer key.
- **Options:** (a) its own category, not readable; (b) unavailable, retried
  in vain until a restore; (c) the catch-all base.
- **Recommendation:** (a): not not-found (OP-09 sees the item), not
  unavailable, not access; the fix is a step on the backend. Source: S3
  `InvalidObjectState`, Azure `BlobArchived`.
- **Decision:** (a).
- **Consistency check:** consistent with D19 and D27. Shared: `OP-01/O9`.
- **Open items:** `OP-01/O9`.

### OP-01/D31: The changed category (AX-10)

- **Scenario:** O2 replaced `a` mid-stream, and the stream's resume request
  fails its ETag check (D22).
- **Options:** (a) its own category, no builtin parent; (b) under
  unavailable.
- **Recommendation:** (a): retrying the same stream cannot help, a new call
  reads the new content, and conditional entries (OP-05) can reuse it.
  Source: OpenDAL `ErrorKind::ConditionNotMatch`; HTTP 412.
- **Decision:** (a).
- **Consistency check:** consistent with D22 and D27. Shared: `OP-01/O9`.
- **Open items:** `OP-01/O9`.

### OP-01/D32: A decode failure (AX-10)

- **Scenario:** whole text, `errors='strict'`, on bytes that are not UTF-8.
- **Options:** (a) the builtin `UnicodeDecodeError`; (b) a library category
  with `UnicodeDecodeError` as parent.
- **Recommendation:** (a): decoding is D5's pure function of the content,
  not a storage failure. Source: `pathlib.Path.read_text`.
- **Decision:** (a).
- **Consistency check:** consistent with D5 and D27 (it is no storage
  failure, so the principle does not wrap it).
- **Open items:** none.

### OP-01/D33: Failures that are not the store's (AX-10)

- **Scenario:** E13 on a Local read (EIO from the disk, ENOMEM, EMFILE); a
  non-str key; `chunks(size=0)`.
- **Options:** (a) an I/O error of the backing storage is the library's base
  category; `MemoryError` and fd exhaustion propagate as raised; caller
  errors are `TypeError` or `ValueError`, before any backend contact;
  (b) everything wrapped.
- **Recommendation:** (a): `except` on the store's base then never hides a
  bug in the caller's code. Source: Python's convention, programming errors
  as `TypeError` and `ValueError`.
- **Decision:** (a).
- **Consistency check:** consistent with D15 (closed stream: `ValueError`)
  and D27. The base category is the catch-all for a storage failure no named
  category fits. Shared: `OP-01/O9`.
- **Open items:** `OP-01/O9`.

### OP-01/D34: The key-refused category (AX-10)

- **Scenario:** `read('../x')` from the root (KEY-004).
- **Options:** (a) a library category, also `ValueError`; (b) a library
  category only.
- **Recommendation:** (a): an invalid argument value, refused by the store's
  configuration (L_api). Source: Python's convention for invalid argument
  values.
- **Decision:** (a). Raised before any backend contact. The categories OP-01
  surfaces, by pre-state or Environment row:

  | Pre-state or row | Category | Builtin parent |
  |---|---|---|
  | ν refuses the input | key refused | `ValueError` |
  | Absent, AbsentAncestor, BlockedByItem | not found | `FileNotFoundError` |
  | Found(e, folder) | not an item | `IsADirectoryError` |
  | E6 | permission denied | `PermissionError` |
  | E11 | authentication failed | `PermissionError` |
  | E15 | not readable | — |
  | E7, E8, E10, E12 | unavailable | — |
  | E9 | timeout, an unavailable | `TimeoutError` |
  | E1 to E5 against a pinned stream | changed | — |
  | E13, disk I/O | base category | — |
  | E13, memory or descriptors | as raised | — |
  | decode under strict | `UnicodeDecodeError` | builtin itself |
  | caller error, closed stream | `TypeError`, `ValueError` | builtin itself |
  | E14 | cancellation, as raised (D20) | builtin itself |

- **Consistency check:** consistent with D9 (shared.md "An unacceptable key
  refused identically by every operation"; this fixes the category). Every
  row of the Environment and every failing row of D9 has a category, so none
  surfaces untyped. Shared: `OP-01/O9`.
- **Open items:** `OP-01/O9`.

### OP-01/D35: Opening a stream (AX-11)

- **Scenario:** open a stream on `missing` or on folder `d`.
- **Options:** (a) every classification failure at the open call; (b) at the
  first read, the open lazy.
- **Recommendation:** (a): a stream the caller holds is for an item that
  existed. Source: session input pitfall "pyarrow's `allow_delayed_open`
  defers open errors to close"; Python `open()`.
- **Decision:** (a). Key refused, not found, not an item, permission denied,
  authentication failed and not readable surface from the open call, which
  makes its first backend request there. A read on the stream surfaces only
  unavailable, timeout, changed, the base category, authentication failed
  (credentials expiring mid-stream) and the caller errors; a whole read
  surfaces everything at its one call.
- **Consistency check:** consistent with D22 (t₀ lies in the open call) and
  D34's table, whose rows this splits by phase.
- **Open items:** none.

### OP-01/D36: Closing a stream (AX-11)

- **Scenario:** a stream meets E8 while releasing its connection in
  `close()`.
- **Options:** (a) `close()` never raises a storage failure; (b) it may raise
  unavailable.
- **Recommendation:** (a): every byte delivered was already checked, and a
  release failure must not replace a `with` body's exception. Source: Python
  read-only file objects; fsspec read-mode close.
- **Decision:** (a). A failure while releasing is not raised; `close()`
  raises nothing but a cancellation (E14, D20).
- **Consistency check:** consistent with D18 (close releases from every
  state) and D10 (release changes no store state).
- **Open items:** none.

### OP-01/D37: A handle's start (AX-11)

- **Scenario:** a caller creates a store for an S3 bucket while offline, then
  reads.
- **Options:** (a) creation contacts no backend; unavailable surfaces at the
  first call; (b) creation connects.
- **Recommendation:** (a). Source: boto3 clients and object_store builders
  (lazy connection); gocloud `OpenBucket`.
- **Decision:** (a). A handle is usable from the moment the caller holds it;
  creating it contacts no backend, so it never fails for E7 to E12.
  Reachability is OP-24's.
- **Consistency check:** binds every operation and fills part of shared.md
  § Lifetime: `OP-01/O10`. How a handle is created and configured stays the
  API spec's (BK-496).
- **Open items:** `OP-01/O10`.

### OP-01/D38: The library's own retries (AX-13)

- **Scenario:** a whole read meets E10 (S3 503 SlowDown) twice, then
  succeeds.
- **Options:** (a) built in, bounded, configurable per store; (b) none, the
  caller retries; (c) each backend client's defaults, a profile row.
- **Recommendation:** (a): a read changes nothing (D10), so repeating it is
  safe. Source: session input, Q4 Retries (object_store built in, timeouts
  retried only when idempotent; s3fs an allow-list); botocore standard mode,
  3 attempts.
- **Decision:** (a). E7 to E10 and E12 are retried with exponential backoff
  and jitter, honouring a backend's retry-after hint, up to a per-store
  attempt limit, default 3 attempts per backend request; only then does
  unavailable or timeout surface. Not found, not an item, key refused,
  permission denied, authentication failed, not readable and changed are
  never retried. A retried whole read still returns one content at one
  instant of its interval (D21). Retry safety rests on no mutation (D10).
  Caller-level retry of a surfaced failure, by a new call:

  | Failure | A new call |
  |---|---|
  | key refused | repeats it: a function of input and configuration (KEY-001) |
  | not found, not an item | repeats it unless the store changes |
  | permission denied, authentication failed, not readable | repeats it until the environment changes |
  | unavailable, timeout, base category | may succeed |
  | changed | reads the content current at its own open |

- **Consistency check:** consistent with D12 (the bound is per request, so a
  call's waiting is at most the attempt limit times the bound plus the
  backoff) and D28. Retry coupled to idempotency binds every entry: shared
  `OP-01/O11`.
- **Open items:** `OP-01/O11`.

### OP-01/D39: Resuming a stream (AX-13)

- **Scenario:** after 30 GB of a 40 GB stream, E8 resets the connection.
- **Options:** (a) the next read resumes from the current position with a
  request conditioned on the pinned content, failing changed if the pin no
  longer holds, unavailable where the backend cannot pin; (b) never resume.
- **Recommendation:** (a). Source: s3fs's ETag-checked range refetch
  (session input pitfall).
- **Decision:** (a). A resume is a retry under D38's limit; once bytes have
  flowed since the last resume, the limit starts afresh. The read continues
  without a gap or a repeated byte, or fails per D22 and D28, moving the
  stream to Failed (D16).
- **Consistency check:** consistent with D6, D16, D22. Which backends can
  pin a new request is a variation point (AX-15).
- **Open items:** none.

### OP-01/D40: The stream's memory (AX-14)

- **Scenario:** a 40 GB stream read in 1 MiB pieces.
- **Options:** (a) promised: memory bounded independently of the item's
  size, no whole copy in memory or on local disk; (b) not promised.
- **Recommendation:** (a). Source: catalogue N-02; session input pitfall
  "cloudpathlib downloads the whole object first".
- **Decision:** (a). An open stream holds at most a per-store buffer bound,
  independent of the item's size, plus what the caller's `read(n)` or chunk
  size asks for, and never stages the item in memory or on local disk. The
  bound's value and the read-ahead are not promised (D41, row 3).
- **Consistency check:** a promise, not a non-promise, recorded under AX-14
  because the register's row 3 bounds it. Consistent with D7 and D39 (a
  resume refetches from the position, never the whole item).
- **Open items:** none.

### OP-01/D41: The non-promise register (AX-14)

- **Scenario:** a test asserts that a successful whole read is one GET, or
  that `chunks(1 MiB)` yields exactly 1 MiB pieces.
- **Options:** (a) adopt rows 1 to 8 below; (b) adopt them but promise
  minimal requests, dropping row 2.
- **Recommendation:** (a): each is a property a caller could infer from the
  name or from `open()` and GET prior art, which no set of backends holds
  uniformly. Source: axes.md AX-14.
- **Decision:** (a). Deliberately not promised, for every OP-01 form:

  | ID | Not promised | Scope |
  |---|---|---|
  | `OP-01/NP1` | Latency and total duration | every call and stream read; D12 bounds waiting, not duration |
  | `OP-01/NP2` | The number of backend requests: D9's listing, retries (D38), resumes (D39), prefetch | every call and stream |
  | `OP-01/NP3` | Chunk boundaries beyond D7, buffer size, read-ahead | the stream |
  | `OP-01/NP4` | When an unclosed stream is released | D17 |
  | `OP-01/NP5` | Out-of-band effects: atime, access logs, billing | D10 |
  | `OP-01/NP6` | Concurrent use of one stream by several consumers | D24 |
  | `OP-01/NP7` | The content seen under O3's in-place modification, beyond D26's per-byte rule | E4, file-system backends |
  | `OP-01/NP8` | The whole forms' memory: they hold the whole content once, plus decoding for text | whole bytes and text |

- **Consistency check:** no row contradicts a decision: each names the
  decision whose limit it marks. NP2 leaves D9's extra listing free to happen
  on the failure path only or otherwise.
- **Open items:** none.

### OP-01/D42: Pinned resume on SFTP (AX-15)

- **Scenario:** an SFTP stream's connection drops at 30 GB; the file handle
  is gone, and a reopened handle cannot prove it is the same file.
- **Options:** (a) a declared deviation: no resume, the stream fails
  unavailable; (b) resume when size and mtime match, which is no pin.
- **Recommendation:** (a): (b) would let D22's "never another content" fail
  silently. Source: SFTP v3 (draft-ietf-secsh-filexfer-02) has no content
  identity.
- **Decision:** (a).
- **Consistency check:** consistent with D22 and D39 (where a backend cannot
  pin, unavailable).
- **Open items:** none.

### OP-01/D43: Static or probed (AX-15)

- **Scenario:** an S3 backend pointed at a non-AWS S3-compatible endpoint
  whose consistency and `If-Match` support are unknown.
- **Options:** (a) static per backend; where one backend serves services
  that differ, the store's configuration selects the declaration, an
  unnamed one getting the deviations; (b) static, the normal values for
  every S3 endpoint; (c) probed at first use.
- **Recommendation:** (a): an undeclared deviation is the one thing AX-15
  forbids, so the unknown case takes the weaker side. Source: unsourced.
- **Decision:** (a). OP-01's variation points:

  | Point | Normal value | Declared deviations, weakest last | Decided by |
  |---|---|---|---|
  | Termination | D12's T_connect and T_idle bound every request | Local, and SFTP's server-side disk: when the OS's I/O completes | D12, D14 |
  | Read-after-write | strong: real-time order after a completed API mutation | eventual | D23 |
  | Pinned resume | a dropped stream resumes pinned, or fails changed | no resume: fails unavailable (SFTP; an S3-compatible endpoint not declared to pin) | D39, D42 |
  | O3 in-place modification | cannot arise (object stores) | arises, with D26's weaker rights (Local, SFTP) | D26 |

  Each is static per backend, selected by the store's configuration where
  one backend serves services that differ; never probed, never requested.
- **Consistency check:** binds every entry's AX-15 (how a variation is
  fixed), so shared: `OP-01/O12`. The S3 endpoints' rows go to a profile
  table beside OP-01's spec, as spec 052's do (RFC-0024 D6).
- **Open items:** `OP-01/O12`.

### OP-01/D44: A caller who needs the stronger guarantee (AX-15)

- **Scenario:** a caller's correctness rests on read-after-write (D23) or

- **Options:** (a) no request in OP-01; the caller learns the store's

- **Recommendation:** (a): it keeps OP-01's signature free of policy. Source:

- **Decision:** (a). OP-01 takes no option that requests or refuses a
  variation.
- **Consistency check:** consistent with D1 to D3 (the signatures). OP-18
  must expose D43's points: `OP-01/O13`.
- **Open items:** `OP-01/O13`.
