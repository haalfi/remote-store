# OP-01: closed decisions

Source: `sdd/observe/records/OP-01.md`. Decisions with Open items `none`: 24.
That field is each decision's own; later open items do not update it (see ../report.md § 2).

```markdown
| Heading | Scenario | Observed |
|---|---|---|
| OP-01/D1: Forms (AX-1) | a caller reads a 2 KB config as text, and a 40 GB item chunk by chunk. | (a) whole bytes, whole text, a sequential binary stream. OP-01 offers three operations: whole bytes, whole text, and a binary stream, each in a sync and an async form. None takes an offset or range: reading at offsets is OP-02's. |
| OP-01/D3: The text form's parameters (AX-1) | an item holds Latin-1 bytes; the caller's locale is cp1252. | (a) `encoding` default UTF-8 and `errors` default strict, both fixed by the library, never the locale. |
| OP-01/D4: The root (AX-1) | `read('')` or `read('a/..')`, which ν reduces to ε, and Ω_S(ε) = Found(r, folder). | (a) no special clause: the root fails as any folder key does. The addressed structure: OP-01 is meaningful exactly for an accepted input k = ν_c(p) with Ω_S(k) = Found(e, item); every other pre-state is a failure whose category AX-3 and AX-10 fix. |
| OP-01/D5: The text value (AX-2) | an item holds `b'\xef\xbb\xbfa\r\nb'`, read as text with the defaults. | (a) exactly `bytes.decode(encoding, errors)`: `'\ufeffa\r\nb'`. text(k, enc, err) = decode(bytes(k), enc, err), where bytes(k) is what the bytes form would return for the same version (AX-8); no newline translation, a BOM kept unless the caller names `utf-8-sig`. |
| OP-01/D6: `read(n)` on the stream (AX-2) | 10 bytes remain and the backend's next network chunk holds 3; the caller calls `read(8)`. | (a) exactly n bytes unless fewer remain, `b''` only at the end, `read()` or `read(-1)` the rest. With r bytes remaining, `read(n)` for n ≥ 0 returns min(n, r) bytes, the next ones of the content; `read(n)` for n < 0 returns all r. Bytes returned across all reads and chunks, in order, are a prefix of the content, the whole content once `b''` is returned. |
| OP-01/D7: The chunk iterator (AX-2) | the caller iterates chunks of size 1 MiB over a 2.5 MiB item. | (a) every chunk non-empty and at most size bytes, their concatenation the remaining content. The iterator takes a positive size; it yields non-empty chunks of at most size bytes, starting at the stream's current position, whose concatenation is the content from there to the end, and stops at the end. Exact chunk sizes are not promised (AX-14). |
| OP-01/D8: Missing keys (AX-3) | `a.txt` is an item; the caller reads `x` (Absent), `p/q/x` with no `p` (AbsentAncestor) and `a.txt/b` (BlockedByItem). | (a) one NotFound category for all three. |
| OP-01/D9: A folder key, and the partition (AX-3) | `d/f` is an item, so `d` is a folder; on S3 a GET on `d` answers 404. The caller reads `d`, or the root (D4). | (a) its own category, not an item; object-store backends tell a folder from absence with one listing request on the failure path only. The complete partition, every form, by pre-state at classification (s2; AX-8 fixes when that instant is): The rows are disjoint and complete: ν refuses or accepts (KEY-001), and KEY-013 gives exactly one Ω case, Found split by TREE-001's partition. Failures that depend on the environment rather than the pre-state (access, transport, decode) are AX-10's. |
| OP-01/D14: Local I/O termination (AX-5) | a Local store on an NFS mount whose server vanished; a read syscall blocks in the kernel. | (a) a profile deviation: termination rests on the OS's I/O completing, no library timeout. Normal value: D12's bound. Declared deviation: Local, and the server-side file system behind SFTP once the SFTP request is sent, terminate when the OS's I/O completes. |
| OP-01/D15: The Closed state (AX-6) | the caller leaves a `with` block, then calls `read(10)` and `close()` again. | (a) Python io semantics: reads raise `ValueError`, a second close is a no-op, in both forms. |
| OP-01/D16: The Failed state (AX-6) | a stream read surfaces a transport failure the library's own recovery (AX-13) could not mend; the caller catches it and reads again. | (a) sticky: every later read raises the same category, close works. A caller who wants to go on makes a new OP-01 call. |
| OP-01/D17: An unclosed stream (AX-6) | the caller drops the last reference to an open stream. | (a) released when collected, with a `ResourceWarning`. When collection happens is AX-14's. |
| OP-01/D19: An item that exists but cannot be read now (AX-7) | O3 moves `cold.bin` to S3 Glacier Flexible Retrieval or Azure Archive; OP-09 still sees the item, but a GET answers "restore first". | (a) add E15, O3 makes an item unreadable in place: E15 joins the Environment. Exposure of OP-01's steps (s1 reduction, s2 classification, s3 transfer, s4 close): s1 is a function of input and configuration (KEY-001), so only E14 reaches it; s4 releases a resource and reports nothing (AX-11). |
| OP-01/D20: Cancellation (AX-7) | an asyncio task awaiting `stream.read(1 MiB)` is cancelled with bytes half-received; or `KeyboardInterrupt` in the sync form. | (a) the stream becomes Closed, its resources released. Cancellation propagates to the caller unchanged; a cancelled stream read releases the stream, which is then Closed (D15). A cancelled whole read or stream open hands out nothing and changes nothing (D10). |
| OP-01/D22: A stream overlapping a write (AX-8) | O1 opens a stream on `a` (v1) and reads 1 GB; O2 replaces `a` with v2 or deletes it; the stream needs a new backend request for the rest. | (a) pinned to the version current at open, or the next read fails with a "changed" category. The stream is one interval operation with one output: the open classifies at one instant t₀ inside the open call (D9's rows), and every byte the stream delivers is a byte of the content at t₀, at its position. If the backend can no longer serve that content, the read that needs it fails with the changed category and the stream is Failed (D16); bytes from another content, or after a gap, are never delivered. |
| OP-01/D25: O3 replaces or deletes in one step (AX-9) | during O1's stream on Local, O3 runs `mv new a` (E3) or `rm a` (E5); on S3, O3 PUTs or DELETEs `a` with the AWS CLI. | (a) the same rights as O2. D21 to D23 apply with O3's E3, E5 and E15 in place of O2's E1 and E2: one content per whole read, a stream pinned to its open's content or failing with the changed category. D23's real-time order is promised only for API mutations; when an O3 change becomes visible is the backend's. |
| OP-01/D26: O3 modifies in place (AX-9) | during O1's whole read or stream of a 10 GB file on Local or SFTP, O3 truncates it to 4 GB, or overwrites bytes 1 GB to 2 GB (E4). | (a) weaker rights, stated: each delivered byte is the file's byte at its position when it was read, no failure promised. Under E4 during an OP-01 call or stream, D21's single instant and D22's pinning are deliberately not promised. What remains: every delivered byte is the byte the file held at that position at some instant between the open and that byte's delivery; the read ends at the end it meets; the call may complete without failing. A non-promise, scoped to E4 on file-system backends (AX-14). |
| OP-01/D32: A decode failure (AX-10) | whole text, `errors='strict'`, on bytes that are not UTF-8. | (a) the builtin `UnicodeDecodeError`. |
| OP-01/D35: Opening a stream (AX-11) | open a stream on `missing` or on folder `d`. | (a) every classification failure at the open call, which costs the first request at open. Key refused, not found, not an item, permission denied, authentication failed and not readable surface from the open call, which makes its first backend request there. A read on the stream surfaces only unavailable, timeout, changed, the base category, authentication failed (credentials expiring mid-stream) and the caller errors; a whole read surfaces everything at its one call. |
| OP-01/D36: Closing a stream (AX-11) | a stream meets E8 while releasing its connection in `close()`. | (a) `close()` never raises a storage failure. A failure while releasing is swallowed (logged), not raised; `close()` raises nothing but a cancellation (E14, D20). |
| OP-01/D39: Resuming a stream (AX-13) | after 30 GB of a 40 GB stream, E8 resets the connection. | (a) the next read resumes from the current position with a request conditioned on the pinned content, failing changed if the pin no longer holds, unavailable where the backend cannot pin. A resume is a retry under D38's limit; once bytes have flowed since the last resume, the limit starts afresh. The read continues without a gap or a repeated byte, or fails per D22 and D28, moving the stream to Failed (D16). |
| OP-01/D40: The stream's memory (AX-14) | a 40 GB stream read in 1 MiB pieces. | (a) promised: memory bounded independently of the item's size, no whole copy in memory or on local disk. An open stream holds at most a per-store buffer bound, independent of the item's size, plus what the caller's `read(n)` or chunk size asks for, and never stages the item in memory or on local disk. The bound's value and the read-ahead are not promised (D41, row 3). |
| OP-01/D41: The non-promise register (AX-14) | a test asserts that a successful whole read is one GET, or that `chunks(1 MiB)` yields exactly 1 MiB pieces. | (a) adopt rows 1 to 8 below. Deliberately not promised, for every OP-01 form: |
| OP-01/D42: Pinned resume on SFTP (AX-15) | an SFTP stream's connection drops at 30 GB; the file handle is gone, and a reopened handle cannot prove it is the same file. | (a) a declared deviation: no resume, the stream fails unavailable. |
```
